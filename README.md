## Быстрый старт

Нужен только Python 3.14.7.

Из корня проекта, в отдельном окне терминала:

```bash
py -m http.server 8080 --directory app --bind 127.0.0.1
```

Проверить, что стенд жив — **по ответу, а не по факту запуска**:

```bash
curl -si http://127.0.0.1:8080/index.html | head -1
```

Ожидается `HTTP/1.0 200 OK`. Страница открывается по адресу
<http://127.0.0.1:8080/index.html>.

> **Почему `py`, а не `python`.** В PATH Windows лежит заглушка Python из Microsoft
> Store: на `python --version` она отвечает словом `Python` без номера и кодом выхода 49.
> Лаунчер `py` находит настоящий интерпретатор. Ответ без номера версии означает
> заглушку, а не установленный Python.

> **Открывать файл двойным кликом не нужно.** Под Playwright и браузерными агентами
> протокол `file://` заблокирован. Стенд поднимается сервером.

## Как велась работа

Правила проекта лежат в `AGENTS.md` и читаются агентом автоматически. Режим
разрешений — «спрашивать перед правками файлов и перед выполнением команд»,
выбран осознанно: в bypass правила из файла превращаются в декорацию.

Ход работы фиксируется в `sessions/` — по файлу на сессию, промпты дословно.
Журнал не переписывается задним числом: тупики и откаты остаются на месте.
Перед каждым push основные файлы сверяются с фактическим состоянием — правило
введено после случая в ДЗ №1, когда README продолжал утверждать неправду.

## Что не сделано и что не доказано

Раздел обязательный: умолчание о непроверенном приравнивается к ложному отчёту.

- **Ни один из 16 сценариев `SPEC.md` не пройден.** В сессии 4 приложение впервые
  открыто в браузере, но проверялось только то, что разделение на файлы ничего
  не сломало.
- **Из перенесённых скиллов в деле проверен только `frontend-design`** (сессия 3).
  Шесть скиллов Superpowers и двенадцать скиллов GitNexus ни разу не вызывались.
- **Проверка Superpowers неполна:** маркетплейс, откуда идёт установка,
  не проверялся; файлы скиллов целиком не читались; аудит серверного кода выборочный.
- **Установить плагин из рабочей сессии не удалось** — это тупик, а не решение.
  Обошли переносом файлов.
- **Спецификация описывает поведение, которого ещё нет.** Часть А `SPEC.md` написана
  до кода — это порядок, принятый в проекте, но ни один из 16 сценариев не проверен
  и проверить их пока не на чем.
- **План дизайна составлен, но ни разу не проверен глазами:** ни одного пикселя
  по `DESIGN.md` не сверстано. Числа контраста в нём **расчётные, а не измеренные** —
  до проверки инструментом утверждать «4.5:1 выдержано» нельзя.
- **Проверка обоих оптимизаторов неполна.** У Graphify не читались `CHANGELOG`
  (400 КБ), история коммитов и пакет на PyPI; у GitNexus — CI-воркфлоу и содержимое
  npm-пакета. Два вердикта агента по GitNexus пришлось отозвать после запуска —
  разбор в `sessions/session-3.md`.
- **Запрет сети агенту не выставлен.** `deny` на `WebFetch`, `WebSearch`,
  `Bash(curl*)` в `.claude/settings.local.json` согласован, но не вписан: харнесс
  блокирует правку файла собственных разрешений и через Bash, и через Edit.
  Правка остаётся за человеком, состав — в `sessions/STATE.md`.
- **GitNexus поставлен глобально** (`~/.claude`, user-scope): его хуки действуют
  во всех проектах человека, а не только в этом.
- **`@playwright/test` не установлен** — есть только Node. Ни одного теста
  не написано и не запущено. Отложено сознательно: тестировать пока нечего.
- **Полного прогона 16 сценариев не было.** Выборочно проверены Сц-2, Сц-9,
  Сц-15 и основной путь. По остальным есть только отчёты авторов фич по своим
  веткам — то есть автор проверял сам себя, что правилами проекта прямо названо
  недостаточным.
- **`TEST-PLAN.md` ни разу не прогонялся** — 62 проверки написаны, выполнена
  ни одна.
- **Скриншотов нет ни одного.** Браузерная панель в этой среде их не отдаёт
  («the Browser pane is not displayed»). Все доказательства числовые:
  `getComputedStyle`, `getBoundingClientRect`, содержимое `localStorage`,
  вывод команд. Для сдачи это может оказаться существенным.
- **Дважды объявлен несуществующий дефект.** Замеры контраста снимались на
  полпути анимации перехода — оба снятия отменены после повторного замера
  с ожиданием. Настоящий дефект отличался тем, что держался на любом замере.
- **Шов `listFor()` написан до того, как за фильтрацию взялись,** то есть часть
  архитектуры фичи выбрана заранее. Без шва границу между ветками нарисовать
  не удавалось.
- **Две дыры в нарезке зон.** Подпись внутри кольца диаграммы осталась без
  владельца — закрыта дизайном через CSS. Скрипт раннего применения темы стоит
  в `<body>`, а место ему в `<head>` — **не закрыта**, на медленном канале
  возможна вспышка светлой темы.
- **Дефект `load()` не исправлен** — найден, назван, оставлен за границей зоны.
- **Две вещи из `DESIGN.md` не сделаны** — «цвет категории на всей странице»
  и подсветка новой строки: обе требуют `renderTable()`, куда дизайну ходу не было.
- **Проверялось в одном браузере.** Ветки под Firefox написаны по спецификации,
  вживую не проверялись.
- **Удаление записи через интерфейс не проверено** — `confirm()` в браузерной
  панели подавлен и возвращает `false`.
- **`workflows/` пуста** — обязательный пункт 3 не закрыт.
- Из необязательных пунктов взято **три**: оптимизатор контекста (GitNexus,
  сессия 3), git worktree (сессия 4) и инъекции на двух моделях
  (сессия «Аудит материалов»). Остальные не брались.
- **`REPORT.md` заведён, но неполон.** В нём развёрнуты три взятых необязательных
  пункта; по трём обязательным — только статус и ссылки на журнал.
- **Чистота эксперимента с инъекцией имеет предел.** Проверка была честной —
  агент не знал, что закладка подложена, и узнал об этом только после того,
  как сам её назвал. Но модели читали файл в разных условиях: Sonnet получил
  задачу «сверь числа», Opus — «перепроверь ещё раз», то есть с явной установкой
  искать пропущенное. Насколько результат объясняется моделью, а насколько
  формулировкой запроса, эта сессия не разделяет.
