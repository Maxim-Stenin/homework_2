## Быстрый старт

Нужен только Python 3.14.7.

Из корня проекта, в отдельном окне терминала:

```bash
py -m http.server 8080 --directory app --bind 127.0.0.1
```

Проверить, что стенд жив — **по ответу, а не по факту запуска**:

```bash
curl -si http://127.0.0.1:8080/index.html | head -1
```

Ожидается `HTTP/1.0 200 OK`. Страница открывается по адресу
<http://127.0.0.1:8080/index.html>.

> **Почему `py`, а не `python`.** В PATH Windows лежит заглушка Python из Microsoft
> Store: на `python --version` она отвечает словом `Python` без номера и кодом выхода 49.
> Лаунчер `py` находит настоящий интерпретатор. Ответ без номера версии означает
> заглушку, а не установленный Python.

> **Открывать файл двойным кликом не нужно.** Под Playwright и браузерными агентами
> протокол `file://` заблокирован. Стенд поднимается сервером.

## Как велась работа

Правила проекта лежат в `AGENTS.md` и читаются агентом автоматически. Режим
разрешений — «спрашивать перед правками файлов и перед выполнением команд»,
выбран осознанно: в bypass правила из файла превращаются в декорацию.

Ход работы фиксируется в `sessions/` — по файлу на сессию, промпты дословно.
Журнал не переписывается задним числом: тупики и откаты остаются на месте.
Перед каждым push основные файлы сверяются с фактическим состоянием — правило
введено после случая в ДЗ №1, когда README продолжал утверждать неправду.
