# Журнал инструментов

> Только дополняется, старые записи не редактируются. Сюда попадает всё, что вы
> добавили в проект или окружение ради этой задачи: библиотеки, CLI-утилиты,
> линтеры, MCP-серверы, плагины и скиллы агента, хуки, внешние сервисы, контейнеры.
>
> Разовый вызов уже установленного инструмента сюда не пишется — он идёт
> в таблицу инструментов внутри файла сессии.
>
> Тупиковая попытка — тоже запись: поставили, не подошло, сняли. Это как раз интересно.

## Шаблон записи

```markdown
## YYYY-MM-DD · Сессия N · <инструмент> vX.Y

- **Тип:** библиотека / CLI / MCP / плагин / скилл / хук / сервис
- **Установка:** `<точная команда>`
- **Зачем:** какую задачу решает
- **Область:** проект или глобально
- **Проверка:** чем убедились, что работает
```

Удалённый или заменённый инструмент фиксируется так же — с пометкой
**удалён** / **заменён на X** и причиной.

## 2026-08-26 · Сессия 2 · Node.js 24.19.0 (LTS) + npm 11.17.0

- **Тип:** среда выполнения
- **Установка:** `winget install OpenJS.NodeJS.LTS --accept-source-agreements --accept-package-agreements --silent`
  (установщик MSI запросил права администратора, подтверждение дал человек)
- **Зачем:** решение человека в сессии 2 после сравнения двух подходов к проверкам.

  `app.js` (`checkAmount`, `parseCSV`, `groupByCategory`) можно покрыть юнит-тестами
  напрямую, без браузера. Побочно открывает браузерные MCP-серверы, которые
  без Node не работают
- **Область:** система (не проект)
- **Проверка:** `node --version` → `v24.19.0`, `npm --version` → `11.17.0`.
  Важно: в уже открытой сессии PowerShell `PATH` не обновляется — версии получены
  после явного перечитывания машинного и пользовательского `PATH`.
  Сам Playwright ещё **не поставлен**: `@playwright/test` и браузеры — отдельный шаг
