### 1. Фильтрация транзакций

Работает целиком на фронте, ничего никуда не отправляет.

**Состав фильтров — три, и только три** (решение человека):

- **тип:** все / доходы / расходы;
- **категория:** одна из существующих в записях;
- **период:** «с» и «по».

**Влияние на остальной экран.** Отфильтрованный список — это не только таблица.
По нему же считаются:

- **итоги** «Доходы», «Расходы», «Остаток» (решение человека);
- **диаграмма** по категориям (решение человека).

**Диаграмма и фильтр по типу.** Вкладки «Расходы по категориям» / «Доходы
по категориям» подчиняются фильтру:

- фильтр «все» — вкладки работают как сейчас, пользователь переключает их сам;
- фильтр «доходы» или «расходы» — диаграмма показывает выбранный тип, вторая вкладка
  видна, но **неактивна** (`disabled`), а не исчезает.

Обоснование того, что вкладка гасится, а не прячется: исчезающий элемент
дезориентирует сильнее погашенного. Решение человека («твоё предложение»).

**Пустой результат фильтрации** — отдельное состояние, не то же самое, что «записей
пока нет». Показывается свой текст и способ вернуться к полному списку
(решение человека).

**Живучесть.** Фильтр **не сохраняется** между перезагрузками страницы
(решение человека). Открыв приложение заново, пользователь видит все свои записи.

**Устаревание результата.** Экран может временно показывать список, не совпадающий
с результатом фильтра. Это **осознанное состояние, а не дефект.**

- Добавили запись, не подходящую под текущий фильтр, — запись всё равно появляется
  **самым верхним элементом таблицы**.
- Удалили запись при активном фильтре — фильтр остаётся.
- В обоих случаях рядом с кнопкой «Фильтры» появляется небольшая плашка
  **«Результат фильтрации устарел»** с кнопкой **«Обновить»** и крестиком.
  Формулировка — человека: устаревает не фильтр (он верен), а показанный по нему
  результат вместе с итогами и диаграммой.
- **«Обновить»** — список пересобирается по фильтру, посторонняя запись уходит.
- **Крестик** — закрывает только плашку. Запись остаётся висеть, список не пересобирается
  (решение человека).
- **Итоги и диаграмма в этот момент считаются по строгому результату фильтра**
  (решение человека). Прямое следствие, которое надо знать заранее: строка в таблице
  видна, а в сумму не входит. При проверках это ожидаемое поведение.

**Стыки с существующими функциями:**

- **выгрузка CSV** при активном фильтре выгружает **отфильтрованный список** — ровно
  то, что видит пользователь (решение человека, сессия 1);
- **загрузка CSV** при активном фильтре **сбрасывает фильтр** (решение человека).

### 2. Тёмная тема

- **Три состояния переключателя:** авто (по системе) / светлая / тёмная
  (решение человека). Без «авто» пользователь, переключивший систему на ночной режим,
  к ней уже не вернётся.
- **Выбор сохраняется** между перезагрузками (решение человека). Хранится отдельным
  ключом `localStorage`, **не внутри данных транзакций** — порча настройки не должна
  задевать деньги.
- Режим «авто» следует системной теме и реагирует на её смену без перезагрузки.

### 3. Вёрстка и дизайн

Задача сформулирована человеком так: «добавить красок на экран, сделать важные
элементы более акцентными, добавить небольших приятных анимаций… следуй трендам…
изучи хорошие работы и цветовые решения. Это на тебе».

**Что решает агент:** конкретная палитра в заданных рамках, типографика, раскладка,
набор и длительность анимаций.

**Жёсткие рамки, которые агент не переступает** (решения человека):

- **розовый цвет запрещён** — включая фуксию, мадженту и розовые сегменты диаграммы;
- светлая тема строится на **нежно-голубой** гамме;
- тёмная тема — на **глубоком тёмно-синем**;
- **адаптив обязателен** — приложение работает на телефоне;
- **внешние библиотеки:** «если потребуются — используем, если можно обойтись —
  обойдёмся». Практическое следствие для приложения без сборки: любая внешняя
  библиотека или шрифт — это сетевой запрос при старте, поэтому по умолчанию
  обходимся системными шрифтами и собственным CSS, а подключение чего-либо извне
  выносится в отдельный вопрос человеку.

**Раскладка** (решение человека): блоки диаграммы и истории транзакций **сужаются**,
справа от них — кнопка **«Фильтры»** и раскрывающаяся панель. Кнопка показывает
**счётчик активных фильтров**.

**Процедура работы над дизайном** — по скиллу `.claude/skills/frontend-design/`:
сначала план из токенов (палитра, роли шрифтов, схема раскладки, «подпись» страницы),
затем самокритика плана на шаблонность, и только потом код. Расхождения скилла
с правилами проекта разобраны в `.claude/skills/SOURCE.md`; в спорных местах
выигрывает человек. Сам план дизайна к моменту записи этой спецификации
**не составлен** — это следующая задача.

### 4. Починка тихой потери данных

Сейчас `save()` (`app/index.html:441`) выглядит так:

```js
try { localStorage.setItem(STORAGE_KEY, toCSV(transactions)); } catch (e) { /* приватный режим */ }
```

Пустой `catch` задумывался под приватный режим браузера, но в него попадает и
переполнение квоты хранилища. Итог: запись видна на экране, в `localStorage` её нет,
после перезагрузки она исчезает молча.

**Как должно быть** (решение человека, вариант агента принят целиком):

- отказ записи **виден пользователю** — сообщением, которое говорит, что данные
  не сохранены и пропадут при перезагрузке;
- **запись остаётся на экране**, а не откатывается: молча стирать введённое хуже,
  чем показать проблему;
- приватный режим и переполнение квоты перестают быть неразличимыми — тихо гасить
  исключение нельзя ни в одном из случаев.

## Чего точно не делаем

- **Справочник категорий** — решение человека, сессия 1. Категории остаются
  производными от транзакций.
- **Поиск по комментарию и фильтр по диапазону сумм** — не входят в состав фильтров.
- **Редактирование существующей записи** — только добавление и удаление, как сейчас.
- **Сортировка по колонкам, пагинация, группировка по месяцам.**
- **Сервер, авторизация, синхронизация, мультивалютность, курсы.**
- **Экспорт в Excel или PDF** — CSV остаётся единственным форматом обмена.
- **Сборка, фреймворк, менеджер пакетов внутри `app/`.** Node в проекте появился
  ради инструментов проверки, а не ради приложения: `app/` остаётся чистыми
  HTML, CSS и JS.

## Допущения

- Приложение открывается в современном браузере с поддержкой CSS-переменных,
  `prefers-color-scheme` и `localStorage`. Старые браузеры не поддерживаются.
- Пользователь один, данные лежат в одном браузере; сценарий «две вкладки одновременно»
  не разбирается.
- Объём данных — сотни записей, не десятки тысяч. Производительность фильтрации
  отдельно не оптимизируется.
- Деньги — рубли, формат `ru-RU`, как сейчас.
- Разделение `app/index.html` на три файла (`index.html`, `styles.css`, `app.js`)
  выполняется **до** работы над фичами: оно нужно, чтобы субагенты не писали в один файл.
