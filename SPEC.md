# Спецификация

Каркас перенесён из ДЗ №1, наполнение — под ДЗ №2. Файл состоит из двух частей.

- **Часть А — эталон ожиданий по продукту.** Каким пет-проект *должен* быть.
  От неё считаются расхождения: без записанного ожидания любая находка сводится
  к спору «а я думал, должно быть иначе».

  считается готовым.

**Порядок обязателен:** спецификация пишется **до** того, как агент начнёт править
файлы. Правит её человек — это самая дешёвая точка вмешательства.

# Часть Б. Спецификация сдаваемой работы

## Состав сдачи

Из таблицы «Что сдавать» задания.

| # | Артефакт | Где лежит | Статус | Готов, когда |
|---|---|---|---|---|
| 1 | Репозиторий | git в корне `result/` | не начато | история видна, ветки на месте |
| 2 | `README.md` | корень | каркас | результат запускается по инструкции без «допишите тут своё» |
| 3 | **Workflow** | `workflows/` | не начато | приложен файл или текст, применим к реальной задаче |
| 4 | **PDF** | корень | не начато | для текстового результата: читаемый документ или презентация |
| 5 | `REPORT.md` | корень | не начато | раздел по каждому пункту, который делали, включая несработавшее |
| 6 | Замеры | `REPORT.md` | необязательно | последовательно против параллельно: время и контекст |
| 7 | Журнал сессий | `sessions/` | ведётся | промпты дословно, размышления, `STATE.md`, `TOOLS.md` |

## Критерии приёмки работы

Из таблицы «Как оцениваем» задания.

- [ ] **Работает.** Результат запускается по инструкции из `README.md`.
- [ ] **Агенты запускались.** По журналу видно, что работа делалась субагентами,
      а не одним чатом: сколько, на что, что вернули.
- [ ] **Workflow есть.** Приложен и применим к реальной повторяемой задаче.
- [ ] **Оформление.** Текстовый результат сдан как читаемый PDF.
- [ ] **Честность.** Прямо сказано, что не сработало. Отрицательный результат
      оценку повышает — тупики не вычищаются из журнала.
- [ ] Секретов в репозитории нет: `.env`, `settings*.json`, история команд, скриншоты.
